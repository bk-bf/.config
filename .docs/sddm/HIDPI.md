# SDDM HiDPI Scaling

SDDM runs as a system service before any user session, so it does **not** read `~/.config/`.
`/etc/sddm.conf` is written by `install.sh` at setup time — not symlinked — because
`QT_SCALE_FACTOR` must be set conditionally based on detected display resolution.

`~/.config/sddm/sddm.conf` serves as the reference template and is source-controlled,
but the live `/etc/sddm.conf` is generated by `install.sh`.

## Problem

On a HiDPI display (e.g. 14" 2880×1800) with Hyprland set to `scale = 2`, SDDM defaults
to 1× scaling — making the greeter tiny. On a 1080p desktop the same setting would make
the greeter render at 2× and appear oversized.

## Fix

`install.sh` detects HiDPI by combining two signals:

1. **Battery present** → it's a laptop
2. **eDP connector exists with height > 1200px** → internal display is high-PPI

eDP (embedded DisplayPort) is exclusively used for laptop built-in screens — desktop monitors always connect via HDMI or DP externally. This correctly handles any HiDPI laptop without hardcoding model names:

| Machine                             | IS_LAPTOP | eDP height | Result                |
| ----------------------------------- | --------- | ---------- | --------------------- |
| Galaxy Book Gen4 (14" 2880×1800)    | ✓         | 1800px     | `QT_SCALE_FACTOR=2` ✓ |
| Future HiDPI laptop (14" 2560×1600) | ✓         | 1600px     | `QT_SCALE_FACTOR=2` ✓ |
| Desktop 4K (27" 3840×2160)          | ✗         | no eDP     | no scaling ✓          |
| 1080p laptop (15.6" 1920×1080)      | ✓         | 1080px     | no scaling ✓          |

## Manual Adjustment

If the auto-detection is wrong (e.g. external monitor not connected at install time),
edit `/etc/sddm.conf` directly:

```ini
[General]
GreeterEnvironment=...,QT_SCALE_FACTOR=2   # add or remove as needed
```

Then update `~/.config/sddm/sddm.conf` to match so it stays source-controlled.
