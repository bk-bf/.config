# Limine boot setup (Galaxy Book)

Migrated from GRUB to the CachyOS **Limine** stack. Limine is UEFI-only here; the ESP
is at `/boot/efi` (`bootctl --print-esp-path`). Kernels/initramfs are copied onto the
ESP under `<ESP>/<machine-id>/` by `limine-mkinitcpio-hook` and booted via `boot():/…`
with BLAKE2 hashes — so Limine doesn't need a btrfs driver at boot.

## Packages

| Package | Role |
| --- | --- |
| `limine` | bootloader |
| `limine-mkinitcpio-hook` | regenerates `<ESP>/limine.conf` + deploys kernels on each mkinitcpio run (`limine-update`) |
| `limine-snapper-sync` | adds snapper snapshot entries to the boot menu; auto-prunes ESP history at `LIMIT_USAGE_PERCENT` |
| `cachyos-snapper-support` → `snapper`, `snap-pac` | pre/post-pacman snapshots (replaces timeshift, which it conflicts) |

## Config layout

- **`<ESP>/limine.conf`** — auto-generated by `limine-entry-tool`; do **not** hand-edit entries.
  Global/header keys (theme, `timeout`, `default_entry`) *are* preserved across regeneration.
- **`/etc/limine-entry-tool.conf`** — shipped defaults (don't edit).
- **`/etc/default/limine`** — our overrides. Tracked as [`limine/default-limine`](../../limine/default-limine).
  Currently just `ENABLE_SORT=yes` (lists `linux-cachyos` before `linux-cachyos-lts`).
- **`default_entry: CachyOS/linux-cachyos`** — pinned by *name* (not index) so the sort can't
  flip which kernel is the default.

## Kernel cmdline (Galaxy Book params)

`acpi_osi`, `mem_sleep_default=s2idle`, `i915.enable_fbc/enable_dc`, `pcie_aspm.policy=powersupersave`
etc. are **not pinned** — `limine-update` reads them from the live `/proc/cmdline`, which already
carries them. To change one persistently, or on a fresh install where the running cmdline lacks
them, pin the full cmdline in `/etc/default/limine`:

```
KERNEL_CMDLINE[default]=root=UUID=<root> rw rootflags=subvol=@ nowatchdog nvme_load=YES zswap.enabled=0 splash loglevel=3 acpi_osi=! "acpi_osi=Windows 2022" acpi.debug_layer=0x00000004 acpi.debug_level=0x00000002 mem_sleep_default=s2idle i915.enable_fbc=1 i915.enable_dc=2 pcie_aspm.policy=powersupersave
```

Then `sudo limine-update`. (`KERNEL_CMDLINE[default]` is used verbatim — it must include
`root=`/`rootflags=`, which `limine-update` otherwise pulls from `/proc/cmdline`.)

## Theme

`cachyos-limine-theme` (diegons490, Catppuccin Mocha) — not a package, applied by hand and tracked:
- [`limine/theme.conf`](../../limine/theme.conf) — header keys, injected after the `timeout:` line.
- [`limine/limine-splash.png`](../../limine/limine-splash.png) — wallpaper, copied to `<ESP>/limine-splash.png`.

`install.sh` reapplies both idempotently (guarded on `^wallpaper:` already present).

## Snapshots

`snap-pac` snapshots every pacman transaction (pre/post); `limine-snapper-sync` mirrors snapper
snapshots into a **Snapshots** submenu. Config mirrors the desktop: single `root` snapper config,
`TIMELINE_CREATE=no` (no hourly timeline). Snapshot kernels in `<ESP>/<machine-id>/limine_history/`
are sha256-deduplicated, so N snapshots on one kernel ≈ one kernel copy. On the small 300M ESP,
`LIMIT_USAGE_PERCENT` in `/etc/limine-snapper-sync.conf` auto-prunes old history.

## Restore on a new machine

`install.sh` handles it (packages → `/etc/default/limine` → theme → `default_entry` → `limine-update`).
Booting itself is registered by `limine-install`/the pacman hook — verify with `efibootmgr` that a
`Limine` entry exists.
